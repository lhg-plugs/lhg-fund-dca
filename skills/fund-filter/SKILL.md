# lhg-fund-filter：品种筛选框架

> **合规声明（必读，置于最前）**：本 skill 只提供**筛选维度框架**，**绝不推荐具体基金产品**；出现具体产品名或 6 位基金代码即视为违规；输出**非投资建议，不构成投顾服务**；历史业绩不代表未来表现；投资有风险。

> 目标：帮小白建立"怎么挑"的标准，而不是告诉他"买哪个"。
> 核心纪律：**只给筛子，不给答案；答案必须由用户自己用筛子筛出来。**

## 1. 何时使用

- 用户问"买哪只基金好"时 → **先纠正问题**（"我不推荐具体产品，但我可以教你怎么筛"），再跑本 skill
- 用户已经有一份候选清单、想"把把关"时 → 跑第 3 节评分卡
- 用户问"指数基金和主动基金哪个好"时 → 跑第 4 节

## 2. 输入与输出

- **输入**：用户的目标期限、风险承受意愿（保守/稳健/进取三选一，不做风险测评替代）
- **输出**：筛选维度清单 + 评分卡模板（空表，由用户自己填）+ 不合格项标红规则

## 3. 六个筛选维度

### 3.1 费率（权重最高）

| 费用项 | 警戒线 | 说明 |
|---|---|---|
| 管理费 | >1.5% 标红 | 主动基金 1.5% 是常见线，指数基金应远低于此 |
| 托管费 | >0.25% 标红 | 超过即贵 |
| 申购费 | >1% 标红 | 定投高频申购，申购费是复利杀手 |
| 赎回费 | 持有 <7 天收 1.5% 是法规 | 看持有期费率表，不看单点 |

**一句话**：费率是唯一"确定"的收益——省下来的费率就是赚到的。

### 3.2 规模

- **过小（<2 亿）**：清盘风险，标红。注意：规模过小还可能触发"连续 60 个工作日资产净值低于 5000 万"的清盘条款，买前看招募书。
- **过大（>500 亿，主动基金）**：船大难掉头，标黄提示。
- **适中**：不加分也不扣分，规模只是门槛项。
- **看趋势不看单点**：规模持续缩水比单点过小更危险，查近 4 个季度规模变化。

### 3.3 跟踪误差（指数类专用）

- 年化跟踪误差 >2% → 标红（指数基金的天职就是"跟得紧"）。
- 对比同标的指数的多只产品时，跟踪误差是核心排序键。

### 3.4 最大回撤

- 看 3–5 年最大回撤，不是看涨幅——**回撤决定了你能不能拿住**。
- 回撤超过用户心理承受线 → 直接淘汰，不谈收益。

### 3.5 成立年限

- <3 年 → 标黄（没经历过完整牛熊）；
- <1 年 → 标红（数据不足以判断）。

### 3.6 基金经理任职（主动基金专用）

- 任职 <2 年 → 标黄；频繁换将 → 标红。
- 只看"现任经理任职以来的业绩"，不看"基金成立以来的业绩"（前任的业绩和现任无关）。

## 4. 指数 vs 主动：选择框架（不给结论）

| 维度 | 指数类通常 | 主动类通常 | 怎么选 |
|---|---|---|---|
| 费率 | 低 | 高 | 在乎成本 → 指数 |
| 对基金经理依赖 | 低 | 高 | 不想研究人 → 指数 |
| 超额收益可能 | 跟随市场 | 可能超额也可能跑输 | 想要超额且接受不确定 → 主动 |
| 持有体验 | 透明 | 看人 | 小白优先透明 |

**框架不给结论**：把两边的利弊摆出来，让用户按自己的偏好选。

选完之后记得回到第 5 节：不管选指数还是主动，六个维度的评分卡都要跑一遍——框架是通用的。

## 5. 评分卡模板（空表，用户自己填）

```markdown
| 维度 | 警戒线 | 候选A | 候选B | 候选C |
|---|---|---|---|---|
| 管理费 | ≤1.5% | | | |
| 托管费 | ≤0.25% | | | |
| 申购费 | ≤1% | | | |
| 规模 | ≥2亿 | | | |
| 跟踪误差（指数类） | ≤2% | | | |
| 最大回撤（3-5年） | 在承受线内 | | | |
| 成立年限 | ≥3年 | | | |
| 经理任职（主动类） | ≥2年 | | | |
| 结论 | | 通过/淘汰 | 通过/淘汰 | 通过/淘汰 |
```

**填写规则**：任何一项标红 → 直接淘汰，不看其他项加分（门槛项不搞加权平均）。

### 5.1 评分卡填写示例（演示格式，不含真实产品）

```markdown
| 维度 | 警戒线 | 候选A | 候选B |
|---|---|---|---|
| 管理费 | ≤1.5% | 0.5% 通过 | 1.8% 标红淘汰 |
| 托管费 | ≤0.25% | 0.1% 通过 | 0.25% 通过 |
| 规模 | ≥2亿 | 80亿 通过 | 0.8亿 标红淘汰 |
| 结论 | | 进入下一轮 | 淘汰（两项标红） |
```

注意：示例中的数字仅为格式演示，不是真实产品数据，不许照抄使用。

## 6. 红线：这些行为一律禁止

1. **推荐具体产品**：说出任何具体基金名称、代码（6 位数字）即违规。
2. **暗示排名**："这只比那只好"也是推荐，话术必须是"按你的框架，A 通过了全部项，B 在费率项标红"。
3. **用历史业绩背书**："过去 5 年涨了 200%"后面必须跟"历史业绩不代表未来表现"。
4. **替用户填评分卡**：候选名单和打分必须由用户自己完成，AI 只给空表和标红规则。
5. **淡化风险**：只谈收益不谈回撤、只谈"长期向好"不谈"可能亏损"——风险提示必须和收益描述同时出现。

## 7. 反模式（不要这么做）

- ❌ 用户问"买哪个"你就真推荐——这是违规，不是 helpful
- ❌ 只看收益率排名筛基金——排名是过去，费率是未来
- ❌ 忽略最大回撤——拿不住的"好基金"等于没买
- ❌ 用"成立以来涨幅"评价现任经理——前任的业绩和现任无关
- ❌ 评分卡替用户填好——填表是用户的决策过程，不许代劳

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 是否出现了具体产品名/6 位代码？→ 有就删，这是红线。
2. 是否有"这只更好"类暗示排名？→ 有就改成框架表述。
3. 评分卡是否是空表？→ 替用户填了就清空。
4. 历史业绩后是否跟了"不代表未来"？→ 没跟就补。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"我有 3 只候选，想筛"走一遍，检查是否只给了空表+标红规则、有无推荐话术漏网。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-fund-dca/issues。
