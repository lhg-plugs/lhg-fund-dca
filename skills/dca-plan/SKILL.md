# lhg-dca-plan：定投计划方法论

> **合规声明（必读，置于最前）**：本 skill 是**个人财务规划工具**，输出**非投资建议，不构成投顾服务**；不推荐任何具体基金产品；历史业绩不代表未来表现；投资有风险，决策需谨慎。

> 目标：把"我想攒 X 万"变成一张可执行、可复盘的定投计划表。
> 核心纪律：**先留应急金，再谈定投；测算用区间，不许给单点"承诺数"。**

## 1. 何时使用

- 用户说"我想定投攒钱"但说不清投多少时 → 跑全流程
- 用户问"每月投多少合适"时 → 跑第 2–3 节
- 已有计划、想检查金额是否合理时 → 跑第 4 节（硬约束检查）

## 2. 输入与输出

- **输入**：目标金额（必填）、期限（必填）、月收入（必填）、应急金现状（必填）
- **输出**：情景测算表 + 定投计划表（Markdown 表格，可打印）+ 末尾合规声明

### 2.1 四个输入，一个不能少

| 输入 | 问法 | 为什么必须问 |
|---|---|---|
| 目标金额 | "这笔钱是干什么用的？要攒到多少？" | 无目标的定投坚持不下去 |
| 期限 | "这笔钱什么时候要用？" | 期限决定每期金额和品种框架 |
| 月收入 | "税后月收入大概多少？" | 硬约束的分母 |
| 应急金 | "有没有留足 6 个月生活费的应急金？" | 没留足就先补应急金，不谈定投 |

## 3. 测算框架：目标倒推 + 情景区间

### 3.1 为什么不用"预期收益率"倒推

定投的未来收益不确定，任何单点收益率假设都是编数字。本 skill 用**情景区间**代替单点预测：

- **保守档**：假设年化 3%（约等于无风险收益水平，仅作测算基准）
- **中性档**：假设年化 6%（测算基准，非预测）
- **乐观档**：假设年化 9%（测算基准，非预测）

每档都必须标注"**测算≠预测，未来收益不确定，实际可能低于三档下限**"。

### 3.2 测算公式（等额定投未来值倒推）

每期金额 PMT、期数 n、每期收益率 r，目标金额 FV：

`PMT = FV × r / ((1+r)^n − 1)`

用三档 r 分别算出三个 PMT，得到"每月投 X–Y 元"的区间。**区间比单点诚实**：告诉用户"按保守档要投这么多"，而不是"每月投 5000 就够了"。

### 3.3 测算表示例格式

```markdown
| 情景 | 假设（测算基准，非预测） | 每期金额 | 说明 |
|---|---|---|---|
| 保守 | 年化 3% | X 元 | 达不到目标的概率低，但每月压力大 |
| 中性 | 年化 6% | Y 元 | 基准情形 |
| 乐观 | 年化 9% | Z 元 | 达标概率高，但别按这档安排支出 |

**测算≠预测**：未来收益不确定，实际可能低于保守档；三档仅用于理解"目标-金额-期限"的数量关系。
```

### 3.4 三个典型目标的测算框架示例

| 目标 | 期限 | 测算思路 | 每期金额区间含义 |
|---|---|---|---|
| 5 年攒 30 万首付 | 60 期 | 三档倒推 | 保守档金额最大，先看超不超收入 30% |
| 10 年攒 50 万教育金 | 120 期 | 三档倒推 | 期数多，保守档与乐观档差距缩小 |
| 20 年攒 100 万养老 | 240 期 | 三档倒推 | 期限最长，复利效应最显著，但不确定性也最大 |

示例只演示"怎么算"，不承诺"能攒到"——任何把示例数字当承诺的解读都是误读。

## 4. 硬约束：三条红线

1. **收入占比红线**：每期金额 ≤ 月收入 × 30%。超过 → blocker，必须降额或延长期限，没有例外。
2. **应急金红线**：应急金 < 6 个月生活费 → 定投计划标注"暂缓"，先输出应急金补足计划。
3. **期限红线**：期限 < 3 年 → 提示"定投熨平波动需要时间，3 年以下慎用定投"，由用户确认后继续。

三条红线是硬门，不是建议。

**红线检查时机**：出计划前查一遍、每次复盘查一遍、收入变化时马上查——红线是持续有效的，不是只查一次。

## 5. 扣款日设计

- 发薪日后 2–3 天：钱还没被花掉，扣款成功率最高。
- 避开信用卡还款日：防止现金流撞车。
- 每月固定一天：纪律来自"不用做决定"。
- 双收入家庭：按先到账的发薪日定扣款日，另一份收入做缓冲。
- 扣款失败处理：3 天内手动补扣并记录原因，连续 2 次失败要检视现金流。

## 6. 定投计划表模板

```markdown
# 定投计划表（<目标名>）

| 项目 | 内容 |
|---|---|
| 目标金额 | |
| 期限 | （X 年 / N 期） |
| 每期金额 | （≤月收入 30%，情景区间 X–Y 元，取值为 Z 元） |
| 扣款日 | 每月 X 日（发薪日后 2–3 天） |
| 品种框架 | （只写类别维度，见 lhg-fund-filter；不写具体产品） |
| 纪律规则 | 止盈/止损/再平衡/暂停加码条件（见 lhg-discipline） |
| 首次复盘日 | |
| 应急金状态 | 已留足 / 暂缓（补足计划见附件） |

> **合规声明**：本计划表为个人财务规划工具输出，**非投资建议，不构成投顾服务**；
> 品种筛选仅提供框架维度，不做具体产品推荐；历史业绩不代表未来表现；投资有风险，决策需谨慎。
```

**每次输出计划表，末尾必须附合规声明**，不许省略、不许缩写、不许"上次说过了"。

## 7. 反模式（不要这么做）

- ❌ 用单点收益率承诺"每月投 X 就够了"——这是编数字，不是测算
- ❌ 应急金没问就出计划——市场一跌用户就要赎回应急
- ❌ 每期金额超过月收入 30% 还说"努努力"——这是把用户推向现金流断裂
- ❌ 计划表末尾漏掉合规声明——一次都不行
- ❌ 在品种栏写具体基金名/代码——这是推荐，不是框架

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 四个输入是否齐了？→ 缺一个就是失职。
2. 是否用了情景区间而非单点预测？→ 单点就是编数字。
3. 三条硬约束是否逐条检查？→ 没检查就补。
4. 计划表末尾是否有完整合规声明？→ 没有就补上。
5. 是否出现了具体产品名/6 位代码？→ 有就删掉。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"目标 30 万、期限 5 年、月收入 2 万"走一遍，检查测算表是否为三档区间、硬约束是否触发、末尾是否有合规声明。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-fund-dca/issues。
